Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talking to a FastAPI service that serves in-memory mock data. Built as a demo codebase for a Claude Code workshop.

System architecture

Three layers, two processes. No database: data is loaded from JSON files into memory when the backend starts.

Data flow

How a filter change on screen becomes a refreshed chart.

  1. User changes a filter FilterBar updates the shared refs in useFilters: period, warehouse, category, order status.
  2. View reacts Each view watches the filters it supports and calls getCurrentFilters(), which maps the period to a month value.
  3. API client builds the request api.js skips any filter set to all and sends the rest as query params via axios.
  4. FastAPI filters in memory The route handler runs apply_filters and filter_by_month over the preloaded lists, matching on order_date. Quarters such as Q1-2025 expand to three months.
  5. Pydantic validates the response Typed models shape the JSON before it leaves the server.
  6. View re-renders Raw results land in refs. Computed properties derive KPIs and chart series, and Vue updates the DOM.

Observations

Things worth knowing before changing the code. These come from reading the source, not from running every path.

Client calls endpoints the server does not define

api.js has methods for /tasks (get, create, delete, toggle) and /purchase-orders (create, get by backlog item). main.py defines no such routes, so those calls would return 404. The server has a CreatePurchaseOrderRequest model and reads purchase orders for the backlog flag, but nothing writes them.

Backlog view is not routed

views/Backlog.vue exists but main.js registers no route for it. Backlog data currently reaches the UI through the Dashboard.

Demo-grade configuration

CORS allows all origins, there is no authentication, and the API base URL is hard-coded. Fine for local use; each would need to change before any real deployment.

Filter support differs by endpoint

Inventory has no time dimension, so it ignores period. The demand and backlog endpoints take no filters at all. Spending ignores filters server-side too, though its view re-fetches when the period changes.
